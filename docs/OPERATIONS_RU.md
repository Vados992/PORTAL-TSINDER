# Эксплуатация исследовательского стенда

## Установка и первый запуск

1. Установите Python 3.11–3.13 и склонируйте репозиторий.
2. Создайте виртуальное окружение. Установите `requirements.lock`, затем пакет
   командой `python -m pip install --no-deps -e .`.
3. Выполните `python -m portal_tsinder init`. Будут созданы SQLite и случайный
   локальный токен, по умолчанию в `.portal`. В Unix файл токена создаётся с 0600.
4. Посмотрите токен через `python -m portal_tsinder token` в своём терминале.
5. Выполните `python -m portal_tsinder serve`. Введите токен на localhost:8000.
6. Запустите M04, проверьте таблицу gates, затем экспортируйте запуск.

Обновление пакетов без повторного тестирования не является проверенным выпуском.
`requirements.lock` фиксирует версии, но не содержит архивы wheels и не обещает
полностью автономную установку. Для offline установки заранее сохраните wheels
через `pip download -r requirements.lock -d wheels`, учитывая целевую платформу.

## Контроллер

Последовательность: `OFF → SAFE → ARMED_ANALOG → RUN_ANALOG`.
Кнопки: Самотест, ARM, START. Уставка безразмерная и ограничена ±0.8; выход ±1.
Отклик — координата обычной демпфированной модели второго порядка.

- HOLD сразу запрещает drive. Для повторного запуска используйте CLOSE, дождитесь
  SAFE, затем ARM/START. Это не аппаратный удерживающий режим.
- CLOSE отключает drive и ждёт пассивного затухания модели до малого envelope.
- E-STOP переводит в LOCKOUT, выход остаётся нулевым.
- `stale_sensor` прекращает поступление симулированных измерений; через 0.25 s
  срабатывает watchdog. `causal_negative` вызывает lockout на следующем шаге.
- `guard_boundary` проверяет закрытие на границе. `clock` и `provenance` — явные
  инъекции отказов симуляции. Они не являются настоящими аппаратными тестами.
- При паузе служебного цикла более 0.25 s во время ARMED/RUN срабатывает watchdog.

Состояние LOCKOUT сохраняется в БД. Незавершённый предыдущий запуск сервиса тоже
приводит к lockout. Перезапуск не означает автоматическое восстановление drive.
Потоки Python и C++ arithmetic checker не заменяют независимо сертифицированный PLC.

Сброс после анализа причины, **при остановленном сервисе**:

```bash
python -m portal_tsinder reset-lockout --reviewer "Operator name" --reason "Reviewed injected stale sensor fault; simulation reset approved"
```

Команда берёт эксклюзивный service lock, проверяет журнал, записывает reviewer и
причину и возвращает следующее состояние в OFF. Личность reviewer — локальная
самодекларация, не независимая аутентификация или peer review. UI сброса не имеет.

## Данные и восстановление

SQLite хранит immutable JSON artifacts, запуск с ссылками на hashes, события с
цепочкой SHA-256 и небольшой изменяемый operational state. Транзакции атомарны;
WAL позволяет чтение и последовательную запись. Команда `verify` проверяет
содержимое и цепочку. Хеши не защищают от администратора, переписавшего всю БД:
для обнаружения переписывания храните head отдельно и используйте
`verify --expected-head SHA256`. При новых корректных событиях head тоже изменится.

Перед резервным копированием остановите сервис чисто и скопируйте весь каталог
данных, включая SQLite WAL/SHM, если они остались. Не копируйте только основной
файл во время активной записи. Копия содержит токен доступа: ограничьте права.
При восстановлении используйте тот же выпуск кода и выполните `verify`.

ZIP одного запуска содержит input, result, package fingerprint, record и manifest.
Это переносимая запись эксперимента; для повторения нужен соответствующий
репозиторий/пакет. В ZIP нет приватного токена, БД других запусков и hardware keys.
HTML отчёт самодостаточен и открывается offline. Строки результата экранируются.

## Docker

```bash
docker compose up --build -d
docker compose exec research python -m portal_tsinder --data-dir /data token
docker compose logs -f research
docker compose down
```

Порт опубликован только на 127.0.0.1, база — в named volume. Внутри контейнера
процесс работает непривилегированно; filesystem read-only, `/tmp` отдельный tmpfs.
`down` не удаляет volume. Не используйте `down -v`, если данные нужно сохранить.
Если Docker build не проверен в текущей среде, это явно указано в VALIDATION.md.

## Развёртывание и пределы

Один Uvicorn worker и один service process на каталог БД. Несколько workers дали бы
несколько независимых симуляций; ServiceLock предотвращает такой запуск.
По умолчанию только loopback, Bearer token и запрет cross-origin запросов.
TrustedHost допускает localhost/127.0.0.1 и testserver для тестов. Адрес 0.0.0.0
предназначен для изолированного контейнера с публикацией loopback.
Публичный доступ, TLS, пользователи/роли, SSO, rate limiting и multi-tenant storage
в этом выпуске не развёрнуты. Не выставляйте исследовательский сервер в интернет.

`/docs` и `/openapi.json` описывают API; protected вызовы требуют токен. Входные
JSON ограничены 1 MB, волновая сетка/число шагов ограничены вычислительным бюджетом,
одновременно выполняются не более двух experiment requests. Сервис не запускает
переданные скрипты, shell-команды или произвольные SymPy-выражения.

## Устранение проблем

| Симптом | Действие |
|---|---|
| 401 | Проверьте токен именно текущего `--data-dir` |
| 422 | Проверьте типы, единицы, диапазоны, имя модели; `true` не число |
| 409 LOCKOUT | Остановите сервис; изучите audit; зарегистрируйте offline review |
| Расчёт волн отклонён | Снизьте points/duration или увеличьте extent/CFL в допустимых границах |
| Символьный solver долго работает | Ожидайте завершения; поддержаны только M00/M01/M04 |
| C++ test skipped | Установите g++/Clang; основной Python сервис от него не зависит |
| Браузерный тест не запускается | Установите Node, Playwright и совместимый Chromium |
| Scientific FAIL | Прочитайте scope: NEC/tidal FAIL может быть правильным результатом модели |

Аппаратных выходов в программе нет. Подключение реальных лабораторных приборов
требует конкретной модели, драйверов, калибровки, ограничений и отдельной проверки.
